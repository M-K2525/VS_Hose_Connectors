# Connector Roll Rotation

## 操作

全8種類のコネクターは、スニーク + Createレンチ右クリックでクリック面に垂直な軸を中心に90度回転する。
この操作は回収と選択解除を置き換える。通常右クリックの手動接続・切断は従来どおり。
通常のレンチ右クリックによる方向回転は行わない。マグネット系も同じ操作に統一する。
反対の面をクリックすると反対向きに回る。4回繰り返すと元の接続方向・姿勢に戻る。
ブロック状態の `roll` は0〜3で、旧ワールドの既存ブロックは0になる。

## 姿勢と接続面

`ConnectorOrientation` が共通の方向計算を担当する。
`rotateAroundFace` は接続方向とモデル上面をクリック面の軸で回し、新しい`facing` と`roll` を求める。
上面の向きも保持するため、方向変更時にねじれや突然の上下反転が発生しない。
通常ホース・電気コネクターの`facing` も上下を含む6方向に対応する。
シャフトの表示軸とCreateの動力接続軸は同じ `shaftAxis(state)` を使う。
回転操作にはCreateの`switchToBlockState` を使う。
シャフトを持つ4種類は`facing` または`roll` の変更を動力接続の変更として扱う。
シャフト軸が同じでもチェーンの伝達符号が変わる場合があるため、姿勢変更時には動力を再計算する。

通常ホースのパイプ面はモデル上面の反対側で、`facing`・`upside_down`・`roll` に追従する。
マグネットホースのパイプ面は `facing` の背面のまま。
電気コネクター2種類は全方向のFE入出力を維持する。
アイテムコネクター2種類は全方向のアイテム能力を公開しており、回転後のシャフト面にも面制限はない。

## チェーン

クライアントの描画とサーバーの動力伝達で同じ回転後のシャフト軸・基準方向を使う。
始点のオフセットはシャフト軸と接続ベクトルの外積で求め、基準方向との内積で符号を揃える。
外積がゼロになる場合は、モデルの回転後の方向をシャフトに垂直な面へ射影して使う。
両端のチェーンは合計距離が短くなる組み合わせで対応付け、伝達の符号にも同じ交換を適用する。
移動方向はシャフト軸と始点オフセットの外積を接続方向へ射影して決める。
ローカル姿勢を計算してからVS/Sableのワールド変換を適用する。

## モデル生成と検証

Minecraftのblockstate JSONはX/Y回転のみのため、追加回転のモデルを生成する。
既存の `roll=0` の姿勢が生成元。要素の座標・回転原点・面・UV・cullfaceをまとめて変換する。
通常ホース・電気コネクターの上下の基準モデルは、従来のnorthモデルから生成する。

モデル更新後は以下を実行する。

```sh
python tools/generate_connector_roll_models.py
python tools/test_connector_roll_models.py
./gradlew.bat build --no-daemon
```

テストはモデル参照、全4姿勢、UV、シャフト軸、チェーンの幾何学的条件を検証する。
ゲーム内の描画と実際の動力伝達・アイテム搬出は別途実機確認が必要。
